# PropRoster iOS foundation

Development branch: `ios-capacitor-foundation-v1`.

The iOS app will use the same production PropRoster accounts, backend, and tenant/property records as the web app. No separate user database is planned.

## Architecture decision

PropRoster is a server-rendered Next.js app with server-side routes and authentication. Do **not** set Capacitor `webDir` to an unverified static export or pretend a static bundle can reproduce those server features. Initial native shell configuration targets the existing HTTPS site using Capacitor `server.url` **for development evaluation only**. Capacitor warns that `server.url` is intended for live reload and not production. Before App Store submission, implement and validate a production-appropriate native delivery strategy, plus substantive iOS functionality. Do not ship the development remote-URL shell to the App Store.

## First verification milestone

1. Install Node dependencies and Xcode on a Mac or macOS CI runner.
2. Install compatible `@capacitor/cli` and `@capacitor/ios` v8 packages; run `npx cap add ios` from the repository root after reviewing the configuration.
3. Validate bundle identifier `com.proproster.app` and display name PropRoster.
4. Run the app in an iOS Simulator and verify login, navigation, property records, Tenant Connect, PropCrew, and Tax Center. Do not use production personal data during early testing.
5. Evaluate camera/document uploads, file handling, deep links, authentication cookies, safe-area behavior, and native navigation. Implement iOS-specific value rather than a simple website wrapper.
6. Resolve the production delivery approach and review Apple's minimum-functionality and payments requirements before TestFlight.
7. Enroll in the Apple Developer Program before TestFlight distribution and App Store submission.

No IPA, Xcode project, TestFlight build, or App Store submission has been generated by this foundation step.
